# 学习时间小助手

[English](README.md) | 简体中文

代码注释、提示词、工具说明与终端文案统一使用英文；助手默认用英文回答，用户明确要求时可以使用其他语言。

这是用于逐块学习的智能体，目前是第三版：普通终端对话、四个本地工具、两个图节点、内存会话历史，以及可保存、更新和删除学习计划的 SQLite 数据库。每条计划只有项目、学习时长、日期三个属性。

每个版本的学习过程、结构图和新增组件统一记录在 [版本学习路线](docs/VERSIONS.zh-CN.md)。第三版使用全新的 SQLite 存储，保留第二版的增删改查接口，从空计划列表开始。

## 启动

在项目根目录的 `.env` 中配置密钥。模型名称和接口地址可以沿用已有配置：

```dotenv
GROQ_API_KEY=填写你的密钥
AGENT_MODEL=openai/gpt-oss-20b
GROQ_BASE_URL=https://api.groq.com
```

在项目根目录运行：

```bash
uv run simple-react-agent
```

如果已经激活并安装了项目的虚拟环境，也可以运行：

```bash
python -m agent_apps.simple_react_agent
```

输入 `exit` 或 `quit`（不区分大小写），或按下键盘中断组合键结束。启动时已有的环境变量优先于 `.env`。

终端使用 Python 标准库 `readline` 处理中文字符的退格和编辑，不自动记录输入历史。当前运行环境为 macOS；不需要额外安装终端输入依赖。

## 先体验三种对话

普通交流，不需要工具：

```text
你：你好，我想开始学习 Python。
助手：……
```

使用工具，可能需要多步计算：

```text
你：每天学习 45 分钟，连续 7 天，一共多少小时？请分步计算。
Tool: Calculating 45.0 multiply 7.0.
Tool: Calculating 315.0 divide 60.0.
Assistant: That is 315 minutes, or 5.25 hours.
```

上面是预期的过程示例，实际回复及工具调用顺序由模型决定。

计算器的 `operation` 参数使用 `add`、`subtract`、`multiply`、`divide`，时间工具返回本地时间，格式为 `YYYY-MM-DD HH:MM:SS`。

理解会话历史：

```text
你：我每天只有 30 分钟学习时间。
助手：……
你：按我刚才说的时间，一周能学多少小时？
助手：……
```

也可以询问“现在几点了？”，观察时间工具的调用。

## 按积木阅读

1. 读 `tools.py`：普通函数怎样通过 `@tool` 变成工具；参数和说明怎样帮助模型选择工具。
2. 读 `model.py` 的 `create_model()`：配置和密钥怎样用于创建模型。
3. 读 `memory.py` 和 `prompts.py`：学习计划怎样写入数据库、查询，再进入系统提示词。
4. 读 `graph.py` 的 `build_graph()`：模型节点决定下一步，工具节点执行操作，条件边决定继续还是结束。
5. 读 `main.py` 的 `chat()`：用户输入怎样变成消息，图返回的完整历史怎样交给下一轮。
6. 最后看 `main()` 和 `__main__.py`，把启动过程连起来。

核心流程只有一条循环：

```text
用户输入 → 模型节点
             ├─ 提出工具调用 → 工具节点 → 回到模型节点
             └─ 给出回答 → 本轮结束 → 等待下一次输入
```

`bind_tools()` 让模型知道工具的名称、参数和用途；模型返回的是调用请求，真正执行工具的是 `ToolNode`。工具结果以消息形式返回给模型，用于继续判断。

模型通常可以根据对话选择工具，但不保证每次都遵循提示词。观察程序实际打印的工具提示，可以确认是否执行了工具；程序不会展示模型的内部推理。

## 第三版：SQLite 学习计划存储

```text
输入：保存学习计划：2026年10月29日，学习Python，时长60分钟。
Tool: Saved study plan: Python, 60 minutes, 2026-10-29.
助手：……
You: exit
```

重新启动后，询问“我有哪些学习计划？”。每次调用模型前会从 `data/study_plans.sqlite` 查询全部计划，并加入系统提示词，因此不需要重新提供项目、时长和日期。

数据库的 `study_plans` 表只有 `project`、`minutes`、`date` 三个业务字段，以项目和日期组成联合主键。查询后仍返回原来的字典列表，供提示词展示，例如：

```json
[
  {"project": "Python", "minutes": 60, "date": "2026-10-29"},
  {"project": "英语", "minutes": 30, "date": "2026-10-29"}
]
```

时长以整数分钟保存，范围为1到1440；日期必须是 `YYYY-MM-DD` 格式的真实日期。项目、时长、日期缺少任意一个时，助手应先询问。遇到“今天”“明天”等相对日期时，先通过时间工具确认；小时数先换算为分钟。

同一项目、同一日期再次保存时更新时长；不同项目或不同日期会新增计划，其他记录保留。普通交流和临时计算不自动保存。比如“把2026年10月29日的Python计划更新为90分钟并保存”，只更新对应的一条。

第一次查询或写入时自动创建数据库，路径相对于 `memory.py` 固定，已加入忽略规则。使用 Python 自带的 `sqlite3`，不需要安装数据库服务。每次操作使用独立连接，退出上下文后提交或回滚，并关闭连接。

## 第三版从空数据库开始

首次访问时只创建空表，历史 JSON 不读取、不导入。第三版新保存的计划会持续保存在 SQLite 中，重新启动后仍能读取，不会每次启动清空数据库。

## 删除学习计划

```text
输入：删除2026年10月29日的Python学习计划。
Tool: Deleted study plan: Python, 2026-10-29.
助手：……
```

删除按“项目＋日期”定位，无需提供时长。条件不明确时助手应先询问；未找到时返回“没有删除任何计划”。其他项目或其他日期的计划保留，最后一条删除后表为空，查询返回 `[]`。删除成功后立即生效，重启也会读到更新后的列表。

## Markdown 提示词目录

```text
simple_react_agent/
├── main.py                       # 终端启动与输入输出
├── graph.py                      # 图构建、节点和路由
├── prompts.py                    # 读取模板、填入计划数据
└── prompt_templates/            # 只存放 Markdown，不放 __init__.py
    ├── system_prompt.md          # 身份、工具使用、计划保存与删除规则
    └── study_plans_prompt.md     # 带有 {plans} 占位符的计划列表模板
```

修改助手行为时编辑对应 `.md` 文件；`prompts.py` 使用 UTF-8 读取它们，再将计划数据填入模板。模板在模块导入时读取，编辑后重新启动程序生效。简短的工具错误提示保留为 `prompts.py` 中的 `TOOL_ERROR_MESSAGE` 字符串。文件名使用小写，Python 常量名使用大写，二者没有必须一致的要求。`graph.py` 通过 `from .prompts import ...` 使用统一入口，`main.py` 从 `graph.py` 导入 `build_graph()`。

## 两种记忆怎样配合

`messages` 是终端循环里的一个列表，保存用户消息、模型回复、工具调用和工具结果。每次调用图时传入完整列表，成功后使用图返回的完整列表替换它。

这里没有检查点。重启程序后对话历史清空；明确保存的学习计划仍保留在 SQLite 中。历史尚未压缩，对话过长时可退出并重新启动。单轮执行设有简单的图步数上限，出错时保留此前成功完成的对话。已经提交的计划操作不会因后续模型请求失败而回滚。

计算器使用浮点数，适合学习时长等日常计算，不作为精确金额计算工具。
