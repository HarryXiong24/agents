# 待办清单助手

[English](README.md) | 简体中文

代码注释、提示词、工具说明与终端文案统一使用英文；助手默认用英文回答，用户明确要求时可以使用其他语言。

这是用于逐块学习的智能体，目前是第五版：普通终端对话、四个本地工具、三个图节点、滚动对话摘要、SQLite 会话检查点，以及待办事项数据库。每条待办仍使用 `project`（名称）、`minutes`（预计耗时）、`date`（安排日期）三个字段。

每个版本的学习过程、结构图和新增组件统一记录在 [版本学习路线](docs/VERSIONS.zh-CN.md)。第五版在第四版持久化会话的基础上增加摘要压缩，待办事项增删改查保持原样，不导入旧 JSON。

## 待办字段与已有数据

这次属于第五版内部的主题调整，尚未进入第六版。已有学习计划直接在待办列表中展示，不改写、不复制；已保存的聊天消息、消息 ID、会话 ID 和摘要不迁移、不清空。后续对话仍沿用第五版正常的摘要压缩行为。

| 存储字段 | 待办含义 |
|---|---|
| `project` | 待办名称 |
| `minutes` | 预计耗时，1～1440 的整数分钟 |
| `date` | 安排日期，格式为 `YYYY-MM-DD` |

保存仍需要三个字段。当前没有完成状态，表达“做完了”不会自动删除，也不能标记完成。同名同日期更新只改变耗时；修改名称或日期会新增记录，不会替换旧记录。

数据库文件与表（`data/study_plans.sqlite`、`study_plans`）、Python 类型与函数（`StudyPlan`、`load_plans`、`save_plan`、`delete_plan`）以及工具名称（`save_study_plan`、`delete_study_plan`）保留旧命名，以兼容已有记录和未完成工具调用。当前提示词和工具返回使用待办文案，启动时不迁移表结构或自动改写数据。包目录与 `simple-react-agent` 启动命令也保持原名。

## 启动

四项配置统一放在这个 Agent 自己的 `src/agent_apps/simple_react_agent/.env`，与 `config.py` 同级。如果文件不存在，复制旁边的 [`.env.example`](.env.example) 为 `.env`，再填写密钥：

```dotenv
GROQ_API_KEY=填写你的密钥
AGENT_MODEL=openai/gpt-oss-20b
GROQ_BASE_URL=https://api.groq.com
SUMMARY_TRIGGER_TOKENS=500
```

在项目根目录运行：

```bash
uv run simple-react-agent
```

每次启动都会先进入会话列表：

```text
Conversations
1. home-todos
2. work-todos
0. New conversation
Type 'exit' to quit.
Choose a conversation:
```

输入已有会话的编号即可继续；输入 `0` 并填写名称即可新建。新会话在发送第一条消息后保存，未发送消息就退出不会产生历史条目。首次启动列表为空，查看菜单和退出不需要 API Key。

如果已经激活并安装了项目的虚拟环境，也可以运行：

```bash
python -m agent_apps.simple_react_agent
```

模块入口也进入同一个菜单。会话名称作为内部 `thread_id`，区分大小写，首尾空白会被移除；新建时拒绝空名称和已有名称。旧的 `default` 等会话仍可从列表选择，不再自动进入默认会话，也不再支持命令行指定会话。

输入 `exit` 或 `quit`（不区分大小写），或按下键盘中断组合键结束。配置只读取 Agent 自己的 `.env`，不受启动目录影响，不使用外层仓库 `.env` 或 shell 中的同名变量。读取不会修改全局 `os.environ`，也不展开 `${...}` 引用。真实 `.env` 已被 Git 忽略，`.env.example` 是可提交的配置模板。

终端使用 Python 标准库 `readline` 处理中文字符的退格和编辑，不自动记录输入历史。当前运行环境为 macOS；不需要额外安装终端输入依赖。

## 先体验三种对话

普通交流，不需要工具：

```text
你：你好，帮我安排日常事务。
助手：……
```

使用工具，可能需要多步计算：

```text
你：7 件事情，每件预计 45 分钟，一共多少小时？请分步计算。
Tool: Calculating 45.0 multiply 7.0.
Tool: Calculating 315.0 divide 60.0.
Assistant: That is 315 minutes, or 5.25 hours.
```

上面是预期的过程示例，实际回复及工具调用顺序由模型决定。

计算器的 `operation` 参数使用 `add`、`subtract`、`multiply`、`divide`，时间工具返回本地时间，格式为 `YYYY-MM-DD HH:MM:SS`。

理解会话历史：

```text
你：我每天有 30 分钟处理家务。
助手：……
你：按我刚才说的时间，一周能安排多少小时？
助手：……
```

也可以询问“现在几点了？”，观察时间工具的调用。

## 按积木阅读

1. 读 `tools.py`：普通函数怎样通过 `@tool` 变成工具；参数和说明怎样帮助模型选择工具。
2. 读 `config.py` 和 `model.py`：前者负责配置读取、解析和校验，后者负责模型创建。
3. 读 `memory.py` 和 `prompts.py`：待办事项怎样写入数据库、查询，再进入系统提示词。
4. 读 `state.py`、`summarization.py` 和 `graph.py`：摘要节点怎样准备上下文，再进入模型与工具循环。
5. 读 `checkpoints.py` 和 `console.py`：存储层怎样返回会话名称列表，菜单怎样选择，以及 `chat()` 怎样将新消息和对应的 `thread_id` 交给图。
6. 最后看 `main()` 和 `__main__.py`：启动过程以及 `SqliteSaver` 的连接生命周期。

核心流程只有一条循环：

```text
用户输入 → 摘要检查 → 模型节点
             ├─ 提出工具调用 → 工具节点 → 回到模型节点
             └─ 给出回答 → 本轮结束 → 等待下一次输入
```

`bind_tools()` 让模型知道工具的名称、参数和用途；模型返回的是调用请求，真正执行工具的是 `ToolNode`。工具结果以消息形式返回给模型，用于继续判断。

模型通常可以根据对话选择工具，但不保证每次都遵循提示词。观察程序实际打印的工具提示，可以确认是否执行了工具；程序不会展示模型的内部推理。

## 对话历史持久化（第四版引入）

运行 `uv run simple-react-agent`，选择 `0`，命名为 `home-todos`，告诉助手“我想整理日常事务”，然后退出。再次启动，按列表中显示的编号选择 `home-todos`，询问“我刚才想整理什么？”。图会根据该会话的 `thread_id` 从 `data/checkpoints.sqlite` 恢复消息。

新建 `work-todos` 会使用另一段独立的历史。每次启动都由菜单选择，不需要记住或传入 ID。编号只是本次菜单的位置，会话名称才是数据库中稳定的标识。

终端每轮只传入新的 `HumanMessage`。`AgentState` 在 `MessagesState` 基础上增加可选的 `summary`，Checkpointer 将摘要与近期用户消息、模型回复、工具请求和工具结果一起保存。

## 第五版：滚动对话摘要

每个新用户轮次第一次调用模型之前，摘要节点估算“已有摘要＋消息历史”的 token 数。达到配置阈值后，用“旧摘要＋较早的完整对话”生成新摘要，原样保留最近 **2 个完整用户轮次＋当前轮**。一轮包含工具请求、工具结果和最终回答，并不是一条消息。

在 `src/agent_apps/simple_react_agent/.env` 中设置 `SUMMARY_TRIGGER_TOKENS`。未配置时默认 **500**，显式配置必须是正整数，修改后重启生效：

```dotenv
# 便于学习时观察触发；后续可以改成 6000 等更大的值。
SUMMARY_TRIGGER_TOKENS=500
```

想用较低阈值测试时，直接把这个本地文件中的值改成 `300` 并重启。全局环境变量不会覆盖本 Agent 的文件配置。

阈值只统计摘要和对话消息，不含固定系统指令、待办事项和工具定义。使用 LangChain 基于字符的 token 估算，不是 Groq 模型精确的 tokenizer。500 适合在约 4～5 轮较详细的交流后观察，但很短的问答可能需要更多轮。即使降低阈值，也必须有超出最近两轮之外的旧对话才能压缩。

快速体验时，新建会话，依次讨论家务、工作事项、可用时间和安排偏好，请助手适当展开回答。成功压缩并完成本轮时会显示：

```text
Context: Earlier conversation summarized; recent turns kept.
```

摘要复用未绑定工具的模型，Markdown 规则要求保留目标、约束、纠正、结论和待解决问题，目标长度约 **100～150 tokens**。这是软目标。有效摘要如果没有缩短旧上下文，就跳过本次压缩，保留原消息和旧摘要并继续回答。空摘要、被截断或要求调用工具仍按错误处理，保留原状态供恢复。尝试生成摘要会增加模型请求、费用和等待时间，即使最终跳过压缩也会产生这次调用；摘要不会作为普通助手回复加入历史。

回答模型接收系统指令、数据库中的最新待办、历史摘要和近期原始消息。摘要属于历史资料，不是新指令；当前待办以数据库为准。摘要过程不会保存或删除待办事项。

压缩通过 `RemoveMessage` 更新当前图状态，SQLite 中的旧检查点暂不清理，所以数据库文件不会自动变小。重启同一会话会恢复摘要和近期消息。第四版旧检查点按空摘要开始，不需要迁移。单条超长输入、保留轮次过长或已有历史特别大时，仍可能超过模型容量；本版不实现分块摘要或严格的上下文总量限制。

## SQLite 待办事项存储（第三版引入）

```text
输入：添加待办：2026年11月4日，整理房间，预计30分钟。
Tool: Saved todo: 整理房间, estimated 30 minutes, scheduled for 2026-11-04.
助手：……
You: exit
```

重新启动后，询问“我有哪些待办事项？”。每次调用模型前会从 `data/study_plans.sqlite` 查询全部待办，并加入系统提示词，因此不需要重新提供名称、预计耗时和日期。

数据库的 `study_plans` 表只有 `project`、`minutes`、`date` 三个业务字段，以待办名称和安排日期组成联合主键。查询后仍返回原来的字典列表，供提示词展示，例如：

```json
[
  {"project": "整理房间", "minutes": 30, "date": "2026-11-04"},
  {"project": "审阅代码", "minutes": 45, "date": "2026-11-04"}
]
```

预计耗时以整数分钟保存，范围为1到1440；日期必须是 `YYYY-MM-DD` 格式的真实日期。名称、预计耗时、日期缺少任意一个时，助手应先询问。遇到“今天”“明天”等相对日期时，先通过时间工具确认；小时数先换算为分钟。

同一名称、同一日期再次保存时更新预计耗时；不同名称或日期会新增待办，其他记录保留。普通交流和临时计算不自动保存。例如“把2026年11月4日的整理房间待办更新为45分钟”，只更新对应的一条。

第一次查询或写入时自动创建数据库，路径相对于 `memory.py` 固定，已加入忽略规则。使用 Python 自带的 `sqlite3`，不需要安装数据库服务。每次操作使用独立连接，退出上下文后提交或回滚，并关闭连接。

## 数据库初始化

待办事项首次访问时创建空表，历史 JSON 不读取、不导入。本次切换为待办主题继续使用已有 SQLite 记录、检查点和摘要。检查点数据库从第四版开始记录会话，不能找回第三版曾经只存在于内存中的对话。

## 删除待办事项

```text
输入：删除2026年11月4日整理房间的待办。
Tool: Deleted todo: 整理房间, 2026-11-04.
助手：……
```

删除按“名称＋安排日期”定位，无需提供预计耗时。条件不明确时助手应先询问；未找到时返回“没有删除任何待办”。其他名称或日期的待办保留，最后一条删除后表为空，查询返回 `[]`。删除成功后立即生效，重启也会读到更新后的列表。

## Markdown 提示词目录

```text
simple_react_agent/
├── .env                          # 本 Agent 的私有配置，不提交 Git
├── .env.example                  # 可共享的配置模板
├── main.py                       # 启动、资源生命周期与组装
├── checkpoints.py               # 检查点路径与已有会话查询
├── console.py                   # 会话菜单、聊天与终端错误提示
├── config.py                     # 本地 .env 读取、解析与校验
├── state.py                      # 近期消息与历史摘要
├── summarization.py              # token 估算、完整轮次选择、摘要更新
├── graph.py                      # 摘要、模型、工具三个节点
├── prompts.py                    # 读取模板、填入待办数据
└── prompt_templates/            # 只存放 Markdown，不放 __init__.py
    ├── system_prompt.md          # 身份、工具使用、待办保存与删除规则
    ├── todo_list_prompt.md       # 带有 {plans} 占位符的待办列表模板
    └── summary_prompt.md         # 滚动摘要规则，不使用工具
```

修改助手行为时编辑对应 `.md` 文件；`prompts.py` 使用 UTF-8 读取它们，再将待办数据填入模板。模板在模块导入时读取，编辑后重新启动程序生效。简短的工具错误提示保留为 `prompts.py` 中的 `TOOL_ERROR_MESSAGE` 字符串。文件名使用小写，Python 常量名使用大写，二者没有必须一致的要求。`graph.py` 通过 `from .prompts import ...` 使用统一入口，`main.py` 从 `graph.py` 导入 `build_graph()`。

`main.py` 打开 Saver，通过 `threads = checkpoints.list_threads(checkpointer)` 获取普通列表，再交给 `console.py` 的 `select_thread(threads)`。菜单不访问数据库；`checkpoints.py` 集中管理 `CHECKPOINTS_FILE` 和会话查询 SQL，`console.py` 管理 `select_thread()` 和 `chat()`。入口直接进入会话列表，不解析命令行参数。

`config.py` 集中管理 `ENV_FILE`、`read_env()`、`SummaryConfig` 及配置解析校验。文件读取属于配置加载的一部分，放在同一模块。`model.py` 使用 `config.read_env()` 创建模型，`main.py` 负责组装应用。

## 两种记忆怎样配合

`data/checkpoints.sqlite` 按 `thread_id` 保存图状态，包括对话历史和执行进度。`data/study_plans.sqlite` 保存三字段待办事项。不同会话的聊天历史独立，但共用同一份待办事项；会话 ID 不是用户账号。

两个文件都能跨重启保留，且已被 Git 忽略。第五版的最新图状态保留近期原文与有损的历史摘要。想开始新对话时在启动菜单选择 `0`，同一会话一次运行一个终端进程。

遇到预期的图、API 或存储错误时，程序结束本次终端会话，保留已经成功写入的检查点。重启后通过 `get_state(config).next` 判断是否有未完成步骤，先用 `invoke(None, config)` 继续，再接受新输入。已经记录完成的步骤会复用；节点中断时若尚未保存结果，可能重新执行该节点。检查点和待办写入属于独立事务，因此不保证工具副作用严格只执行一次。后续模型失败也不会回滚已提交的待办。

计算器使用浮点数，适合预计耗时等日常计算，不作为精确金额计算工具。
